# 书签研究（中文阅读版）

[English execution Skill](../../SKILL.md) · **中文阅读版**

使用用户提供的普通链接、画布路径或已注册来源。答复优先遵循本次指定语言，其次是保存的 `research.response_language`；`auto` 跟随任务语言，都未指定时用英文。尚不了解已保存偏好时先读 `get_settings`。将确定的语言要求传给子代理并写入研究 brief，保留原始引文与标识符。参考文件按需读一种语言即可。原书签包保持不变，本地备注不进入公开查询。

## 按实际需求选择

| 用户请求 | 执行流程 |
| --- | --- |
| 找书签、统计数量、查看备注或画布关系 | 查询本地元数据。 |
| 核实一个链接或少量事实 | `quick`：读取 URL，给出有依据的简短答复。 |
| 比较收藏的工具、调查开放问题 | `agentic`：当前宿主模型搜索／读文、判断证据，再补查缺口。 |
| 研究完整清单／数据包、保留进度、交付可复核报告 | `deep`：在宿主调查上增加固定范围、证据记录、独立审阅和覆盖检查。 |

优先遵循本次明确深度，再遵循保存的偏好；表格用于 `auto`。深度与范围分别判断：专题比较只覆盖该专题，整包研究保留全部原始 URL。需要时简短说明范围，然后执行；仅询问能力不自动启动研究。宿主搜索和深研无需专业研究 API Key。

## 入口与快速查证

使用当前宿主实际暴露的 MCP 工具。旧目录缺少所需工具或参数时，使用同包 CLI：`<插件根目录>/src/cli.py`。插件根目录是英文 Skill 所在目录的 `../..`，调用时使用绝对路径。其他命令名称见 [CLI 参考](cli.md)。

每个需要联网研究的新问题开始前调用 `research_readiness`（CLI `readiness`）。传入实际 `host` 和当前确实观察到的宿主工具；用户明确限定服务时也传入对应 providers。检查遵循 cached/always/manual 偏好，同一轮调查不要反复强制探测。离线书签查询不需要联网就绪检查。连接或授权失败后检查受影响服务，修复后再刷新。保留用户显式选择的服务；可选 API/MCP 故障不阻塞其他可用路线。

区分已配置密钥、工具目录可达、实际检索成功和宿主 OAuth 登录。缺少可选原生研究 MCP 或协作能力时，宿主仍可自己完成搜索阅读循环。安装配置或排障使用 CLI `setup` 和 [配置指引](settings-and-archive.md)。不要让用户在对话中粘贴密钥；终端支持隐藏输入或环境变量。实际样例检索会使用服务额度，仅按选择执行；就绪检查不会启动专业研究任务。

已知公开 URL 直接调用 `fetch_web({urls:[url]})`；CLI 等效命令为：

```sh
python3 <插件根目录>/src/cli.py fetch-web 'https://example.com/page' --timeout 20
```

`--timeout` 限制单个服务 HTTP 请求，整条瀑布流可能更久。除就绪检查外，普通链接查证不需要导入包、创建研究档案或加载其他参考文件。公开 GitHub README 也走这条路径。

`fetch_web.pages` 按 URL 返回一份选中的正文，各次尝试保留状态与归档路径。读取相关内容并引用原 URL；完整服务响应仍在归档内，需要时可用 `raw:true`（CLI `--raw`）返回。注意归档错误和完整性标记，抽取文本不证明取得了完整或实时原页。

## 搜索、判断、补查

由当前宿主模型先处理。已有 URL 直接读取；需要发现来源才用 `search_web`，随后读取关键页。普通比较可以直接答复；需要保存进度或报告时再建立研究档案。

省略 provider 使用保存的回退设置。默认读取先 Exa，未解决 URL 再并发 Parallel + Jina；搜索先 Exa + Parallel，无可用结果的查询再走 Tavily + 有 Key 的 Jina。显式 provider 限定本次服务。保留已成功项，检查未解决项、跳过的服务和预算。

非空响应不等于已回答。核对页面身份、相关段落、日期／版本及引文能否支撑结论。正文不相关、过时或不足时，只补查受影响的 URL／问题：换用允许的服务、链接指向的官方说明、原站 API／Markdown 视图或可用且获授权的浏览器。在研究会话内记录 uncertain／rejected 来源判断，为合理的新读取使用新的 operation ID；重放旧操作不会得到新文本。替代页面可以支持答案，不能冒充已读原始 URL。

选择或排查服务时读 [服务接入](research-workflow.md)；研究代码、issue、release、私有访问或 Git 同步时读 [GitHub 边界](github-and-sync.md)；系统比较、冲突或榜单分析时读 [研究方法](research-methods.md)。简单事实核实不需要加载完整方法流程。

## 画布语境

画布输入先读 [阅读协议](package-semantics.md)，会话内复用。仅在字段新颖／冲突或用户要求核对特殊约定时查原包指南。

- 用 `index_status` 查已注册来源；新手动导出用 `sync_package` 的 `snapshot`，用户指定持续目录时用 `live`。只有确认完整镜像才用 `completeness:complete`，局部导出／单卡用 `partial`；同一画布改路径沿用真实 source ID。[来源生命周期](source-lifecycle.md) 用于迁移、恢复和监控。
- 在 `search_bookmarks` 中合并目标，跟随每个目标的分页。匹配是字面元数据匹配，短名称须对照标题和域名判断。保留 ID、URL 和分组语境；本地标题不证明网页能力。
- `get_context` 携带 `item_id` 返回书签与祖先，并提供卡片说明、分组和有向边。栏目概览不枚举全部书签；从祖先取得 folder ID 后再限定目录查询。
- 检查 `source.state` 并说明待同步状态；error／unavailable 时只有用户接受旧索引才用 `refresh:false`。历史快照用 `source_history`。研究清单和 Wiki 保留版本，新鲜度提示要求复核，不代表自动重做调查。

## 深研与协作

需要此模式时读 [深研流程](deep-research.md)，以明确问题和完整输入开始：

- 普通书签：`research_start` 传 `urls:[...]`，重复位置仍保留在固定清单中，无需注册画布。
- 画布数据包：传已索引的 `source_ids`，默认整包。用户明确要求子集时才用 `scope_mode:subset` 及选中的 inventory ID 或书签引用。
- 没有原始书签清单的公开问题可省略两类输入；仅写在 brief 里的 URL 不进入覆盖统计。

跟随全部 `research_inventory.next_offset`。区分原始 `u-...` inventory ID 与正文 `sN` evidence ID。阅读、审阅原文，记录带引文结论与逐项清单判断。已有判断用 `research_record.entries` 批量提交（至多 50 条），附稳定的 `batch_id`；后续批次引用真实返回 ID。检查覆盖差集，直到完成或预算用尽。失败说明、批量排除、搜索摘要和外部报告的引文列表不能证明完整原始来源已审阅。

主代理负责综合。当前允许委派且具备能力时，给独立读者／核验者明确范围、问题、语言、相关指引与真实 MCP／CLI 入口；执行细节按需读 [宿主工作流](host-workflows.md)，适用 Codex、Claude、Pi、DSH，不假定子代理继承上下文。不能委派时由当前代理复核并说明。

专业研究服务用于具体子问题或用户明确指定的任务；使用前读 [研究服务](research-services.md)。保留显式服务选择和已知 run ID，不替换仍在运行或结果未知的任务。`research_route` 只建议、不启动；保存的 API 偏好不替代宿主首轮处理。

## 交付与偏好

简单问题直接答复。报告结束前，对照证据与反证复核实际交付的短答；压缩结论时保留原有条件和限制。`research_finish` 生成报告、来源和覆盖文件，分别说明逐项交代、可用正文、实质审阅与问题完成度。覆盖、答案证据及冲突检查通过才用 `completed`，否则保留 `incomplete` 与缺口；继续未完成档案先写 `resume`。保存状态不代表后台代理。

用户要求将结论保存在 Wiki 或知识库中时才编写 Wiki；发表、lint 和有真实评审标签的质量比较见 [Wiki 与评测](wiki-and-evaluation.md)。引文／哈希检查不证明语义正确。

配置问题用 `get_settings`，长期偏好用 `update_settings`，临时选择用本次参数。[配置与归档](settings-and-archive.md) 说明保存位置；索引、归档和产出均位于原包之外。
