## 已完成的修复

### 网页正文与证据归属

- 修复批量响应中 Markdown 代码围栏遮蔽页面边界、导致正文被归到另一 URL 的问题。无法确定归属的区块保留原始响应，不作为可引用正文返回，可通过供应商回退或单 URL 重抓恢复。
- 同时执行单页和总正文预算，默认总预算为 100,000 字符。通过 `capture_id` 和 `offset` 继续读取已存快照，无须再次请求网络。
- 区分完整存档 SHA 与返回切片的 `text_sha256`。旧版提取结果在复用前根据原始响应重新核对归属；正文哈希相符也不能绕过归属校验。
- 保存供应商、抓取时间和版本观察记录；拒绝经符号链接逃逸存档根目录的路径。

### Wiki 存储、查询与更新

- 增加 SQLite 增量候选索引，以 Unicode 字符片段、字面匹配和显式别名召回候选，只对命中页校验证据；支持页面自定义别名。它不提供向量或语义召回。
- 缓存 Wiki 目录摘要，保存页面时不再逐个读取所有旧修订。派生索引失败不撤销已提交的 Wiki 写入，查询可回退到修订扫描。
- 分开报告证据完整性和新鲜度。记录跨研究任务、跨抓取的 URL 版本；过期、新版本、抓取时间未知、刷新失败以及相关书签或链接变化会提示复核。
- 默认 `wiki.max_source_age_days = 30`，可配置。内容相同的新抓取可续期，不重写 Wiki 历史；历史快照晚导入不会替代较新的抓取观察。
- 检查引用书签及其相关分区、祖先、分组、节点和边关系，避免无关书签改名引发复核。局部文档和推论仍保留整体输入依赖。
- 新增 `wiki_refresh`，按批抓取已引用 URL，保存观察结果，返回 changed / unchanged / unverified、受影响页面、存档读取参数及续页信息。URL 反向依赖和 Wiki 链接可以传递复核提示。
- 刷新不会自动改写已审核论点、Wiki 页面或书签。作者复核后仍通过带预期修订号的写入提交新版本。

### 并发与输出规模

- MCP 网络任务使用最多 4 个工作线程，同时运行和排队合计最多 16 个请求；本地 SQLite 操作留在传输线程，慢抓取不再阻塞本地查询。
- 响应允许乱序完成，保留对应请求 ID，并串行写入输出；拒绝重复活动 ID 和超量排队。正常输入结束会等待已接收请求完成。
- 取消仅停止尚未执行的任务。已经发出的 HTTP 请求会完成并保存结果和回执，不宣称支持底层网络强制取消。
- MCP 和 CLI 的上下文输出默认每个集合最多 200 行，支持集合选择及独立续页；后台清单仍保留完整数据。
- 单目标书签查询复用已有结果，同次操作缓存分区元数据。

## 当前边界

- 新鲜度依据抓取时间与已知版本；供应商可能返回缓存。`origin_current_verified` 始终为 `false`，不把“快照未损坏”解释为“源站现在未变化”。
- 当前为按需刷新，没有后台定期监测网页；不会自动同步作者写入的书签标题或 Wiki 结论。
- 显式别名改善部分中英文和常用表述匹配，但不具备向量检索、语义判定或完整问答召回率评测。
- 并发改进解决慢网络占用本地工具的问题；已发送请求的强制取消和更大规模索引性能不在本次验证结论内。
