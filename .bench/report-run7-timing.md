## 4. 三个根因（已实测，不是猜测）

### 4.1 CLI 在读不了库时直接躺平（最大的一刀，≈45s）

```
$ touch ~/.local/share/bookmark-research/.zz_probe   → Operation not permitted
$ sqlite3 index.sqlite3 "CREATE TABLE ..."          → attempt to write a readonly database
$ sqlite3 "file:...?mode=ro" ".tables"              → ✅ 正常
```

- 文件权限本身是 `rw-r--r--` / `drwxr-xr-x`，是**宿主沙箱**（workspace-write）禁止写 workspace 外。
- `BookmarkIndex.__init__` 无论读写都 `sqlite3.connect(path)` + `executescript(SCHEMA)`，`--no-refresh` 也照样跑 DDL → 必然失败。
- 后果：4 步 CLI 试探里 2 步失败，然后 7 步手写 sqlite。**`?mode=ro` 明明可用。**

### 4.2 `walk` 的 schema 承诺了 `item_id`，handler 只认 `ref`（2 步 + 11.5k 字符）

```
walk(item_id=...)  → {"error":"walk requires ref or source_id"}
walk(ref=...)      → 返回 canvas group/section，不返回文件夹子项
```

发出去的是 `traverse_graph` 的 schema（含 item_id/node_id），`src/mcp_server.py:1083-1092` 直接拒绝。
而真正想做的事是"列出这个文件夹的子项"——没有对应原语，只能 `read` 一个再看看。

### 4.3 `locate` 回包太胖（8 次 = 65,028 字符 ≈ 16k tok）

每条 hit 带 `why{terms,fields,field_weights,weight,match_mode}`、`version_id`，外加 `coverage`、`candidates`、`next`、`more.handle`。单个 folder 继承命中就 21,574 字符。
本次 8 次 locate 的字符数：9,957 / 1,319 / 2,930 / 1,069 / 103 / 13,830 / 14,246 / 21,574。
